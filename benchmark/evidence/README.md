# Benchmark Evidence — QA Sign-Off Process

This directory holds evidence artifacts generated by benchmark runs against OSS seed repos.

## Directory Layout

```
evidence/
  <slug>/
    <slug>-<timestamp>.json    # raw BenchmarkRecord array from runner.ts
    sign-off.md                # QA sign-off notes for this repo/run
```

## Sign-Off Criteria

A benchmark run is considered QA-signed-off when all five checks pass:

1. **Non-zero records** — the run produced at least one `BenchmarkRecord` with a resolved `commitSha`
2. **No `unknown`-only change types** — at least one commit must classify to a named `ChangeType` (not solely `unknown`)
3. **Blind spots detected** — at least one commit must have `blindSpotsDetected.length > 0` for TS repos; Python repos may be exempt until Python AST support lands
4. **Output file integrity** — the JSON output passes `BenchmarkRecordSchema` validation for every entry
5. **No clone errors** — the run log contains no unhandled `ENOENT` or `git clone` failures

## How to Sign Off

After a run completes, create `evidence/<slug>/sign-off.md` with:
- Date and run timestamp
- Pass/fail for each of the five checks above
- Any anomalies or notes
- Reviewer name/initials

## What This Evidence Is Used For

Signed-off runs are used to validate that the blind spot detection pipeline fires correctly on real-world OSS commit history. They feed into `ExpansionCandidate` generation and are referenced when pitching optinum to external stakeholders as credibility evidence.
